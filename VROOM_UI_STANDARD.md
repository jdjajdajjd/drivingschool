# Vroom UI Standard

Дата аудита: 2026-05-09  
Источник истины: `/student` в залогиненном состоянии.  
Цель: весь Vroom должен ощущаться как один мобильный продукт, а не набор отдельных демо-экранов.

## 1. Ключевое правило

Если экран плохо работает на 390–430 px, экран не готов. Desktop должен быть расширением mobile-first системы, а не наоборот.

## 2. Эталонные паттерны из `/student`

### 2.1 Структура

- Один основной вертикальный поток.
- Крупные смысловые секции сверху вниз.
- Горизонтальные списки для дат, фильтров, слотов, быстрых вариантов.
- На мобильном нет мелких таблиц. Списки превращаются в карточки.
- Нижняя навигация допустима только если контент имеет безопасный нижний отступ и не перекрывается.

### 2.2 Карточки

Базовая карточка Vroom:

- фон: белый;
- радиус: 20–24 px;
- padding: 16–20 px;
- border: тонкий светлый;
- тень минимальная или отсутствует;
- внутри есть понятный заголовок, короткий secondary text, статус/бейдж и действие рядом с объектом.

Карточка не должна быть просто контейнером. Она должна помогать принять решение.

### 2.3 Empty state

Плохой вариант: `Нет данных`.

Правильный Vroom-паттерн:

1. Что сейчас: `Заявок пока нет`.
2. Почему это нормально: `Когда ученик оставит заявку, она появится здесь`.
3. Что делать: `[Создать заявку]` или `[Открыть страницу школы]`.

### 2.4 Типографика

- H1 mobile: 28–32 px, 800/900, tight tracking.
- H2: 22–24 px, 800.
- Card title: 17–20 px, 700/800.
- Body: 15–16 px, readable line-height 1.4–1.55.
- Caption/meta: 12–14 px, но не бледнее WCAG AA.
- Button: 15–16 px, 700/800.

Нельзя делать весь интерфейс мелким серым текстом.

### 2.5 Цветовые роли

- Background: светлый тёплый/нейтральный фон.
- Surface: белые карточки.
- Primary text: почти чёрный.
- Secondary text: уверенный серый, не бледный.
- Primary action: Vroom blue `#1F2BD8` / `#2442D8`.
- Success/free: зелёный.
- Warning: жёлтый/оранжевый.
- Error/destructive: красный.
- Extra/category: фиолетовый.

Цвет в Vroom всегда означает роль, а не украшение.

### 2.6 Кнопки и CTA

На экране один главный CTA. Остальные действия визуально ниже.

Primary:

- 48–56 px height;
- синий фон;
- белый текст;
- радиус 14–18 px;
- текст короткий и глагольный.

Secondary:

- 44–52 px height;
- светлый/белый фон;
- тонкая граница;
- понятная подпись.

Text/Ghost:

- только для вторичных действий;
- не конкурирует с primary.

Запрещено:

- кнопка говорит одно, но ведёт в другое место;
- две одинаково яркие кнопки без приоритета;
- CTA ниже длинной формы без sticky-состояния;
- `Открыть`, `Страница`, `Добавить` без контекста, если непонятно что именно.

### 2.7 Touch targets

- Любой интерактивный элемент: минимум 44 px по высоте, лучше 48 px.
- Между соседними тач-элементами минимум 8 px.
- Чекбокс кликается всей строкой, не только маленьким квадратом.
- На мобильном фильтры-чипы не ниже 36–40 px, ключевые действия 48–56 px.

## 3. Аудит текущего состояния

Аудит снят скриптом `scripts/hermes-ui-audit.mjs`. Скриншоты и raw report:

- `reports/hermes-audit/audit.json`
- `reports/hermes-audit/audit-raw.md`
- `reports/hermes-audit/390-student-logged-in.png`

### 3.1 Хорошо

- `/student` в logged-in состоянии задаёт правильный продуктовый тон.
- Landing уже ближе к цельному продукту: ясный оффер, крупные CTA, нет мелких таблиц.
- Admin shell частично приведён к mobile-first: есть bottom nav, крупные карточки на главной.
- Build и typecheck проходят.

### 3.2 Главные проблемы

1. **Админка ещё не единая система.** Разные страницы выглядят как разные реализации.
2. **Мелкие touch targets.** Особенно settings, slots, students filters, desktop top nav.
3. **Settings перегружен.** Это desktop-form, ужатая в мобильный экран.
4. **Bottom nav перекрывает контент на full-page screenshots и рискует мешать длинным формам.** Нужен больший нижний safe padding и отдельный sticky-save паттерн.
5. **CTA copy местами слабый.** `Страница`, `Открыть`, `Добавить`, `Создать серию` требуют контекста.
6. **Booking flow без H1.** На `/school/virazh/book` audit нашёл missing-h1.
7. **Public school/login/register имеют мелкие элементы.** Нужна унификация тач-зон и заголовков.
8. **Superadmin выглядит отдельным продуктом.** Его надо привести к тем же tokens и nav/CTA правилам.

## 4. Приоритеты правок

### P0, первая пачка

1. Admin shell:
   - безопасный bottom padding;
   - top bar copy `Страница` → `Открыть сайт` / `Публичная страница`;
   - desktop nav touch targets не ниже 40–44 px;
   - единый container rhythm.
2. Admin settings:
   - уменьшить перегруз;
   - сделать sticky save или понятный save block;
   - категории превратить в удобные chips с подсказкой `Можно выбрать несколько`;
   - checkbox строкой 48 px;
   - destructive section отделить как `Опасная зона`.
3. Admin slots/students:
   - фильтры/чипы минимум 40–44 px;
   - главные действия 48 px;
   - empty states по Vroom pattern.

### P1

1. Admin dashboard/bookings/instructors/branches: унифицировать карточки, статусы, кнопки.
2. Public school + booking flow: добавить H1, привести CTA/чипы/инструкторов к `/student`.
3. Login/register: увеличить touch targets, убрать лишне мелкие действия.

### P2

1. Superadmin: привести shell и карточки к Vroom standard.
2. Desktop refinement: не просто растягивать mobile cards, а делать спокойную 2-column operations layout.
3. Bundle/chunk optimization после визуальной стабилизации.

## 5. Definition of Done

Перед показом пользователю:

- `npm run typecheck` проходит;
- `npm run build` проходит;
- сняты скриншоты 390, 430, 1365;
- нет горизонтального скролла;
- нет интерактивных элементов ниже 44 px для ключевых действий;
- CTA говорит ровно то, что делает;
- нижняя навигация не перекрывает важный контент;
- экран выглядит как часть того же продукта, что `/student`.

## 6. Запреты

- Не делать dark theme.
- Не делать generic SaaS dashboard.
- Не использовать gradient text.
- Не использовать декоративный glassmorphism.
- Не превращать мобильные списки в мелкие таблицы.
- Не добавлять кнопки ради кнопок.
- Не скрывать бизнес-ошибки красивой оболочкой.
