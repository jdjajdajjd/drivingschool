# Vroom / DriveDesk — полноценный дизайн-план админской панели

Дата: 2026-05-07  
Фокус: админка автошколы для директора/администратора 40+, без технической каши, в стиле приложенных референсов.

---

## 1. Главная проблема сейчас

Текущая админка частично перекрашена, но не спроектирована как цельный продукт.

Что не работает:

1. **Нет понятной карты действий.**  
   Директор видит набор блоков, но не понимает: что делать первым, что важно сегодня, куда нажимать.

2. **Много одинаковых карточек.**  
   Карточки выглядят как шаблон, а не как рабочий инструмент. Референсы работают иначе: там есть крупные смысловые зоны, цветные акценты и ясная композиция.

3. **Слабая визуальная иерархия.**  
   Важное и второстепенное выглядят почти одинаково.

4. **Формулировки местами всё ещё системные.**  
   Админка должна говорить языком автошколы: ученик, занятие, инструктор, филиал, расписание, запись.

5. **Мобильный вид должен быть не “сжатый desktop”, а отдельный рабочий сценарий.**  
   На телефоне директор должен за 10 секунд понять: сегодня есть занятия или нет, есть свободное время или нет, что нажать.

---

## 2. Цель дизайна

Сделать админку похожей не на CRM-шаблон, а на простое приложение для управления автошколой.

Админка должна отвечать на 5 вопросов:

1. **Что сегодня происходит?**
2. **Кто записан на занятия?**
3. **Есть ли свободное время для учеников?**
4. **Что нужно добавить или исправить?**
5. **Где ученики входят и записываются?**

Если экран не отвечает хотя бы на один из этих вопросов — он лишний или плохо собран.

---

## 3. Дизайн-направление по референсам

### 3.1. Что берём из референсов

1. **Мягкий светлый фон**  
   Не серый `#F4F5F6`, а тёплый молочный/бежевый.

2. **Крупные цветные смысловые блоки**  
   Не 10 белых карточек подряд. Один-два сильных цветных блока задают структуру.

3. **Цвет как смысл, а не украшение**
   - зелёный — управление, готово, нормальное состояние
   - жёлтый — сегодня, внимание, быстрое действие
   - синий — записи/информация/ссылка
   - фиолетовый — расписание/планирование
   - оранжевый — ученики/люди/активность
   - красный — отмены/ошибки/опасные действия

4. **Иконки внутри цветных капсул**  
   Иконка не должна болтаться просто чёрной линией. Она живёт в цветном квадрате/круге и помогает быстро читать экран.

5. **Большие понятные надписи**  
   Но не огромные ради красоты. Крупным должно быть только главное число/действие.

6. **Меньше рамок, больше воздуха и группировки**  
   Референсы выглядят дорого не из-за теней, а из-за ясной группировки.

## 4. Цветовая система

### База

```txt
Фон страницы:        #F7F1E7  молочный беж
Карточка:            #FFFFFF
Тёмный текст:        #15120E
Вторичный текст:     #7C736A
Слабый текст:        #A69C92
Линия/разделитель:   rgba(21,18,14,0.06)
```

### Смысловые цвета

```txt
Зелёный основной:    #10231C  hero / управление / главный акцент
Зелёный мягкий:      #EAF7EE  готово / успешно
Зелёный текст:       #188447

Жёлтый:              #F4D35E  сегодня / важное / внимание
Жёлтый текст:        #7A5A00

Синий мягкий:        #EAF0FF  записи / ссылка / информация
Синий текст:         #3156D4

Фиолетовый мягкий:   #F2EAFF  расписание / планирование
Фиолетовый текст:    #7B3FD6

Оранжевый мягкий:    #FFF0D8  ученики / люди / активность
Оранжевый текст:     #C26A00

Красный мягкий:      #FFECEA  отмена / проблема / удалить
Красный текст:       #D94A38
```

### Правило

Один экран не должен использовать больше **3 активных цветовых смыслов** одновременно, иначе снова будет визуальный шум.

## 5. Типографика

Шрифт оставляем: **Manrope**.

### Размеры

```txt
Главный заголовок desktop: 44–56 px, weight 900
Главный заголовок mobile: 30–36 px, weight 900
Заголовок блока:          20–24 px, weight 900
Обычный текст:            14–16 px, weight 600–700
Подпись/метка:            11–12 px, uppercase, weight 900
Числа:                    32–54 px, weight 900
```

### Запрет

Не делать все заголовки огромными.  
Крупными должны быть только:
- название текущего экрана
- главное число
- главный CTA

## 6. Иконки

Используем HugeIcons, но по смыслу.

| Раздел | Иконка | Цвет |
|---|---|---|
| Сегодня | Dashboard / Calendar | зелёный |
| Записи | Clipboard / Calendar | синий |
| Расписание | CalendarAdd / Calendar | фиолетовый |
| Ученики | User | оранжевый |
| Инструкторы | UserMultiple / Car | зелёный |
| Филиалы | Location | красный/коралл |
| Настройки | Settings | нейтральный беж |
| Ссылка ученикам | LinkSquare | синий |
| Успешно/готово | CheckmarkCircle | зелёный |
| Удалить/отмена | Cancel/Delete | красный |

### Правило для иконок

Иконка всегда находится в цветной капсуле:

```txt
размер капсулы: 44–56 px
скругление: 16–22 px
иконка: 20–24 px
```

Не использовать голые серые иконки в важных местах.

## 7. Формулировки: как должна говорить админка

### Общий тон

Просто, как сотруднику автошколы:
- “Добавить время”
- “Открыть записи”
- “Сегодня занятий”
- “Свободное время”
- “Ссылка ученикам”
- “Что настроено”
- “Что сделать дальше”

### Запрещённые слова в видимом UI

```txt
слот / слоты
tenant
workspace
RPC
slug
white-label
модуль
конфигурация
сущность
```

### Замены

```txt
слот                → время / занятие / свободное время
модуль              → дополнение / возможность
slug                → адрес страницы
workspace           → панель школы / кабинет школы
бронь               → запись
создать слот        → добавить свободное время
bulk                → серия занятий
status              → состояние
```

## 8. Общая структура админки

### Desktop

```txt
[Левое меню 300px] [Контент]

Контент:
1. Верхний смысловой блок страницы
2. 2–3 главных показателя / действия
3. Основная рабочая зона
4. Второстепенная боковая зона
```

### Mobile

```txt
[Верхняя панель]
[Главное действие]
[Сегодня / важные числа]
[Основной список]
[Дополнительные действия]
```

На mobile нельзя просто ставить desktop-блоки один под другим без переработки.

## 9. Экран 1 — “Сегодня” / Dashboard

### Назначение

Первый экран после входа. Должен быть понятен человеку, который вообще не знает CRM.

### Структура

1. **Hero-блок**
   - заголовок: “Управление автошколой”
   - текст: “Записи, расписание, ученики и инструкторы — в одном месте”
   - CTA: “Добавить время”, “Открыть записи”
   - цвет: тёмно-зелёный `#10231C`

2. **Жёлтый блок “Сегодня”**
   - “0 занятий” или “5 занятий”
   - кнопка “Посмотреть записи”
   - если занятий нет: подсказка “Добавьте свободное время или отправьте ссылку ученикам”

3. **Три компактные смысловые карточки**
   - Завтра
   - Свободное время
   - Инструкторы

4. **Ближайшие занятия**
   Табличный список, не карточки:
   - дата/время
   - филиал
   - ученик
   - телефон
   - инструктор
   - состояние

5. **Правая колонка**
   - Что настроено
   - Ссылка ученикам

### Нельзя

- “Рабочий день”
- “Очередь”
- “Готовность” как главный термин
- “Основа”
- 6 одинаковых карточек подряд

---

## 10. Экран 2 — “Записи”

### Назначение

Администратор должен быстро понять: кто записан, когда, к кому, что с записью сделать.

### Структура

1. **Hero-блок синий**
   - “Записи учеников”
   - “Все занятия, переносы и отмены”
   - главное число: активные записи

2. **Фильтры одной строкой / компактным блоком**
   - поиск по имени/телефону
   - период: сегодня / завтра / неделя / будущие
   - филиал
   - инструктор
   - состояние

3. **Основной список как таблица**

Desktop:
```txt
Дата и время | Ученик | Телефон | Инструктор | Филиал | Состояние | Действия
```

Mobile:
```txt
Дата и время
Ученик + телефон
Инструктор / филиал
Кнопки: Перенести / Отменить / Проведено
```

### Действия

- “Перенести” — синий/фиолетовый
- “Отменить” — красный
- “Проведено” — зелёный

### Нельзя

- отдельная карточка на каждую запись с кучей мелких блоков
- “активные / всего / сегодня” как три большие карточки сверху, если они не помогают действию

---

## 11. Экран 3 — “Расписание”

### Назначение

Самый важный рабочий экран. Нужно убрать ощущение сложной настройки.

### Главная идея

Не “создание слотов”, а **“Добавить свободное время для записи”**.

### Структура

1. **Hero-блок фиолетовый**
   - “Расписание”
   - “Добавьте время, когда инструктор может принять ученика”
   - CTA: “Добавить серию занятий”

2. **Левый блок — добавить время**
   Пошагово:

```txt
1. Где проходит занятие?       Филиал
2. Кто ведёт?                  Инструктор
3. На какие даты?              Дата от / дата до
4. В какие дни?                Пн Вт Ср Чт Пт Сб Вс
5. В какое время?              Начало / конец
6. Сколько длится занятие?     90 минут
```

3. **Правый блок — предварительный итог**
   До создания показывать:

```txt
Будет создано примерно: 12 занятий
Инструктор: Иван Петров
Филиал: Центральный
Период: 10–20 мая
```

4. **Нижний список расписания**

Desktop:
```txt
Дата | Время | Инструктор | Филиал | Тип | Состояние | Действие
```

Mobile:
```txt
Дата / время
Инструктор
Филиал
Состояние
```

### Цвета состояний

```txt
Свободно     зелёный
Записан      синий
Скрыто       серый/красный
Прошло       серый
```

### Нельзя

- слово “слот”
- “bulk”
- “режим single/bulk” в UI
- перегруженная форма на всю ширину без объяснения

## 12. Экран 4 — “Ученики”

### Назначение

База учеников. Должно быть как список людей, а не карточки профилей.

### Структура

1. **Hero-блок оранжевый**
   - “Ученики”
   - “Контакты, ближайшие занятия и история”

2. **Поиск + фильтр**
   - имя/телефон
   - все / есть занятия / без занятий / есть отмены / лимит

3. **Список учеников**

Desktop:
```txt
Ученик | Телефон | Ближайшее занятие | Всего записей | Состояние
```

Mobile:
```txt
Имя
Телефон
Ближайшее занятие
Состояние
```

### Нельзя

- карточка на каждого ученика с 4 мини-блоками
- “лимиты по бронированию”

---

## 13. Экран 5 — “Инструкторы”

### Назначение

Понять, кто работает, какая машина, есть ли свободное время.

### Структура

1. Hero зелёный.
2. Кнопка “Добавить инструктора”.
3. Список:

```txt
Инструктор | Телефон | Машина | Филиал | Занятий впереди | Свободное время | Состояние
```

### Карточку можно использовать только для профиля инструктора, но список должен быть табличный.

---

## 14. Экран 6 — “Филиалы”

### Назначение

Понять адреса и где проходят занятия.

### Структура

1. Hero коралловый/красно-бежевый.
2. Кнопка “Добавить филиал”.
3. Список:

```txt
Название | Адрес | Инструкторы | Будущие занятия | Состояние
```

### Дополнительно

Карту пока не делать, если нет нормального API. Лучше чистый адрес и понятная кнопка.

---

## 15. Экран 7 — “Настройки”

### Назначение

Редкие настройки, не ежедневная работа.

### Структура

Разделить на понятные группы:

1. **Данные школы**
   - название
   - телефон
   - адрес
   - категории

2. **Страница для учеников**
   - адрес страницы
   - описание
   - кнопка открыть

3. **Правила записи**
   - длительность занятия
   - сколько занятий можно выбрать
   - можно ли отменять

4. **Внешний вид**
   - цвет
   - логотип позже

### Нельзя

- технические поля без объяснения
- “slug”
- “tenant”

Состояния: свободно / записан / отменено / готово / нужно.

## 17. Mobile rules

Для 390px:

1. Hero не выше 260px.
2. На первом экране без скролла должны быть видны:
   - название экрана
   - главное число/состояние
   - главное действие
3. Списки — не карточками, а компактными строками.
4. Фильтры по умолчанию свернуть после первого экрана, если их больше 3.
5. Кнопки минимум 44px высотой.
6. Не больше двух CTA рядом.

## 18. Desktop rules

3. Основной layout:

```txt
aside: 30–40%
```

4. На desktop списки должны быть табличными, не карточными.

## 22. Короткое правило для разработчика

Если страница выглядит как “много белых карточек с текстом” — это неправильный дизайн.

Правильная страница:

```txt
1 сильный цветной блок
1 главное действие
1 основной список
1 боковой блок с подсказкой/итогом
цветные иконки по смыслу

```

## 23. Итог

Полноценный дизайн должен быть не “дороже карточки”, а “директор понял за 10 секунд”.

Главный принцип:

> Не показывать систему. Показывать работу автошколы.
