# Vroom Admin Rebuild Plan

## Что убираем

Текущая версия не должна быть базой:
- красные аварийные состояния на пустом аккаунте;
- большие карточки ради карточек;
- декоративная статистика с нулями;
- длинные списки без сценария;
- разные визуальные языки между Dashboard / Bookings / Slots;
- экран, который выглядит как debug-панель, а не продукт.

## Главная идея

Админка vroom — это не CRM и не аналитический кабинет. Это рабочий стол маленькой автошколы/оператора:

1. Быстро понять, что сегодня происходит.
2. Быстро принять звонок и записать ученика.
3. Быстро собрать расписание.
4. Не забыть закрыть/перенести/отменить занятие.
5. Видеть, что школа готова принимать записи.

Тон: спокойный, уверенный, диспетчерский. Без паники. Без “красного, потому что не заполнено”.

## Визуальный язык

### Основа
- Светлый фон `#F4F6F8`.
- Основные рабочие поверхности белые.
- Тёмный графит только для главных действий/выбранных вкладок.
- Синий — ссылка/навигация/вторичное действие.
- Красный — только реальная ошибка: просроченное активное занятие, конфликт, неудачная операция.

### Форма
- Минимум rounded, но не “кирпич”. Радиус 12-16 на больших контейнерах, 10 на controls.
- Больше воздуха на пустом аккаунте.
- Больше плотности на рабочих журналах.
- Мобильный first: одна колонка, sticky action снизу где нужно.

### Типографика
- Заголовки короткие: “Запуск школы”, “Сегодня”, “Записи”, “Расписание”.
- Не писать “НЕ ГОТОВА К ЗАПИСИ”. Вместо этого: “Нужно 4 шага для запуска”.
- Объяснения человеческие, не системные.

## Информационная архитектура

### Dashboard: “Запуск / Сегодня”

Два состояния:

#### A. Пустая школа
Экран запуска:
- Hero: “Запустим запись учеников”
- Подзаголовок: “Добавьте телефон, филиал, инструктора и первые окна расписания.”
- Progress: 0/4, 1/4, etc.
- Четыре setup steps:
  1. Контакты школы
  2. Филиал / место встречи
  3. Инструктор
  4. Окна расписания
- Primary CTA = следующий незавершённый шаг.
- Secondary CTA = “Посмотреть публичную страницу”.
- Ни одной статистики с нулями.

#### B. Рабочая школа
Оперативная сводка:
- Сегодня: ближайшее занятие, сколько занятий, сколько свободных окон.
- Требует внимания: переносы, отмены, просроченные активные занятия, нет окон на неделю.
- Быстрые действия: принять звонок, создать окна, открыть расписание.
- Лента ближайших занятий.

### Bookings: “Записи”

- Верх: быстрый ввод звонка: имя, телефон, дата, окно.
- Ниже: журнал записей.
- Режимы: Сегодня / Будущие / Прошлые / Все.
- Строка записи:
  - время и дата;
  - ученик + телефон;
  - инструктор + филиал;
  - статус;
  - действия: перенести, провести, отменить.
- На mobile действия сворачиваются в компактные кнопки.

### Slots: “Расписание”

- Не список карточек, а планировщик.
- Верх: создать окна (серия / одно окно) компактно.
- Сводка: свободно на 7 дней, занято сегодня, пробелы недели.
- Табель окон:
  - дата;
  - время;
  - инструктор;
  - филиал;
  - статус;
  - кто записан.
- Группировка по дням должна быть читаемой.

## Функциональный план

### Сейчас в рамках быстрого rebuild
1. Полностью заменить Dashboard empty-state.
2. Убрать красный/тёмный аварийный hero на пустой школе.
3. Свести Dashboard к двум чистым состояниям: setup и operations.
4. В Bookings/Slots привести стиль к одному языку: светлые поверхности, спокойные акценты.
5. Не ломать существующую бизнес-логику.

### Потом
1. Inline-комментарии к записи.
2. Быстрый выбор слота из календарной сетки.
3. Недельная сетка инструкторов.
4. Поиск ученика при звонке.
5. Нормальная пустая демо-школа с seed data для продаж.

## Критерии готовности

- На пустом аккаунте экран выглядит как понятный запуск, не как ошибка.
- На мобильном первый экран отвечает: “что делать дальше?”
- Нет красной тревоги без реальной аварии.
- Нет больших нулевых dashboard-карточек.
- Dashboard, Bookings, Slots выглядят как части одного продукта.
- Typecheck/build проходят.
